Get started

Desktop apps. Entirely in Go.

GOUI is a lightweight, modern Go GUI framework for Windows, macOS and Linux. No cgo. MIT licensed.

Get startedTry the demo

A desktop toolkit, not a web stack.

Use Go's toolchain, embed your assets, and ship a focused native application. GOUI handles the parts a desktop interface needs, without becoming an all-purpose platform SDK.

Your existing toolchain

Build with CGO_ENABLED=0. Native APIs are loaded at runtime, so building your application requires no C/C++ compiler or development headers.

One binary, one app

Windows and Linux applications can run as a single executable. On macOS, wrap the binary in an .app for identity, icons and signing. Native system libraries are still required.

Modern, with native roots

Light/dark styles and accent colors meet native window chrome, text layout, IME, clipboard and file dialogs. Choose declarative views or imperative widgets.

A window in a few lines.

A window is an ordinary Go value. This complete app opens a native window — run it, then grow from here.

go get github.com/golang-gui/goui@v0.3.0
Follow the complete tutorial →
main.go
package main

import "github.com/golang-gui/goui/ui"

func main() {
	ui.Run("org.golang-gui.hello", func(app ui.App) ui.RootView {
		return ui.Window("main").
			Title("Hello World").
			Content(ui.Label("Hello GOUI!"))
	})
}

Made for AI-assisted development.

GOUI ships an official skill your coding assistant can install, publishes each running window as a plain-text semantic snapshot a language model can read, and can accept real input through an opt-in local automation protocol.

Prompt
Install the GOUI application development skill following https://github.com/golang-gui/goui/blob/main/skills/INSTALL.md.

One prompt to install the skill

The official goui-app skill follows the Agent Skills format: send one install instruction to your coding tool and it gains GOUI application guidance. Whether a tool loads skills is decided by the tool itself. Install instructions ↗

Semantics as plain text

Every window publishes a semantic snapshot — role, text, bounds, focus, supported actions — as JSON a plain-text model can read, so understanding the UI does not require vision. See it in the demo →

Automation through real input

The opt-in local gui/dev server lets agents read snapshots, dispatch pointer and key events, and commit text through the normal input path. An explicit import plus GOUI_DEV_ADDR enables it, so it never ships in release binaries. Protocol reference ↗

Lightweight, with the numbers in context.

With Go 1.25.8, CGO_ENABLED=0, -trimpath and stripped symbols, the documented minimal app builds are 4.46–4.75 MiB. Linux/X11 Software 1x reference measurements report 28.6 MiB PSS for a minimal app and 46.2 MiB for the demo. These are development measurements—not release download sizes, Go heap sizes, or promises for every platform.

Simple doesn't mean incomplete.

GOUI provides the foundations and controls for small desktop apps, from utilities and note-taking tools to data-oriented workspaces.

Everyday controls

Buttons, labels, icons, menus, dropdowns, check/radio buttons, switches and linear or circular progress indicators.

Editing that feels native

Unicode text editing, CJK IME, selection, undo/redo, clipboard, keyboard shortcuts and Tab focus navigation.

Data and flexible layouts

Constraint-based boxes, wrapping, scrolling, overlays, split views, virtualized lists, trees and tables with custom cells.

Multi-window workspaces

Reorder tabs, transfer them between windows, detach into a new window, and use native drag and drop.

Graphics and appearance

Style-aware SVG icons, light/dark modes, accent colors, HiDPI, transparency, shadows and frame-driven animation.

System and developer tools

File dialogs, file-access credentials, timers, system settings, URL/file opening, build tooling and opt-in semantic UI inspection.

Use only the layers you need.

Three desktops. Clear requirements.

No cgo is a build property, not a claim that the application has no runtime dependencies.

Windows

Windows x64 · Win32 windows · DirectWrite text · Direct2D, OpenGL or Software drawing.

macOS

macOS Apple Silicon · AppKit windows · Core Text · OpenGL or Software drawing. Signing and notarization remain application distribution steps.

Linux

Linux x64 · X11 · Pango/Cairo text · OpenGL or Software drawing. Needs native X11, GL, GLib, Fontconfig, Pango/Cairo and GTK runtime libraries. Wayland sessions require XWayland; behavior must be checked on the target desktop.

v0.3.0 APIs are still evolving. Touch, additional platforms and window systems, more application controls, and continued performance work are on the roadmap.

A few useful answers.

Is GOUI a web wrapper?

No. GOUI draws widgets through native graphics backends and uses native text layout. It does not embed a browser engine.

Do I need GCC or cgo?

No C/C++ compiler is required to build your app. GOUI supports CGO_ENABLED=0 and binds native libraries at runtime. Runtime library requirements still apply.

Can I cross-compile?

Supported targets can be built with the Go toolchain without cgo. Packaging, signing and actual platform validation are separate steps; a successful build does not verify native behavior.

Is everything in v0.3.0 stable?

No. This release is intended for building small applications and gathering practical feedback. Public APIs continue to evolve; pin a version and review changes when upgrading.

Can an AI agent read and operate my GOUI app?

Yes, with three building blocks: install the official goui-app skill for guidance, read the semantic snapshot as plain text for UI state, and optionally enable the local gui/dev server for snapshot, event and text APIs through real input dispatch. Automation stays in development builds and does not ship to users.
